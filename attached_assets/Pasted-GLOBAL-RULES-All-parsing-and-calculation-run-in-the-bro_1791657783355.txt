GLOBAL RULES
- All parsing and calculation run in the browser. The file never leaves the user's
  device. Use a standard CSV library (e.g. PapaParse) and keep calculation logic in
  pure, unit-tested functions.
- Read-only: never modify the uploaded file or its values. Keep every original row
  with its original CSV line number, exactly as imported (text values untouched).
- Never guess or silently fix. A missing value shows "Cannot calculate" with a
  one-sentence reason; blank is never treated as zero; "Not logged" is not zero.
- Changeover time and unplanned downtime are always separate; never added, subtracted
  or merged automatically.
- No causal claims; wording is "observations", any explanation is labeled hypothesis.
- Plain language in the UI, 14px minimum text, no jargon.
- The code references only internal roles (run, event type, quantity, start, end...),
  never source column names or plastics words. Labels (e.g. "Scrap", "Changeover")
  come from the user's configuration. Quantity unit is a setting (kg by default).

STAGE 1: Upload, file check, mapping, saving
- Real CSV upload and the built-in samples.
- File check right after upload: row/column counts, header row found or not, delimiter
  and encoding, guessed file shape (one row per event / one row per run, user can
  override), column types, and a list of file problems with their CSV line numbers
  (title rows above the header, blank rows, repeated header rows inside the data,
  totals rows mixed with data, mixed date formats, numbers stored as text such as
  "1,000"). Do not fix them silently: show each problem and let the user choose
  (ignore this row, treat as header, keep as is). If the file cannot be read or no
  column can identify a run, explain why in plain language.
- Mapping: suggest column matches from an editable synonym list (user confirms);
  user-defined event types (label, matching source values, kind: quantity or timed)
  with the plastics set pre-filled; for "one row per run" files, map columns to
  measures instead; timed events accept start+end columns OR one duration column;
  optional roles (line, machine, mold, shift, product); custom fields; configurable
  date format and decimal separator.
- Save imports and mapping profiles in the browser (IndexedDB/localStorage) so they
  persist after reload; show a clear note that clearing browser data removes them.
  Profiles store settings only, not the file.
- Show the original rows table with line numbers.

STAGE 2: Calculations and data checks (real, on the imported data)
- Group rows into runs by the mapped run ID (or order ID).
- Templates: Ratio, Duration, Total, plus Difference, Count, Rate per hour, Average,
  each with a live example result. Default "Scrap rate" = Scrap / Material input.
- Data checks with CSV line references: identical duplicate (count once, show both
  rows, flag), same ID with conflicting values (block only the affected metrics, show
  all rows), missing required event or value, zero denominator, invalid quantities or
  timestamps, material balance (good + scrap vs input, tolerance setting), overlapping
  changeover/downtime time ranges (warn, keep both durations as recorded).
- Per-run results screen with data-health badges, "Blocked metric is not a blocked
  run".

STAGE 3: Comparison, evidence, export
- Run list (search, filters, sorting) and picking Baseline and Compared run; similar
  runs by transparent rules (same line/mold/machine, input within tolerance, custom
  comparison attributes) with "not assessed" when a column is unmapped.
- Plain-language answer sentence, metric cards and full table; difference = Compared
  minus Baseline; percentage points for rate differences.
- Evidence drawer for every number and every difference: formula with actual values,
  source rows with line numbers and original values (for "one row per run" files,
  highlight the exact cell), excluded rows with reasons, mapping used.
- Export comparison CSV and printable page including warnings, units and evidence.
